# Guarded serial fresh execution

`run_fresh_cohort` connects an already admitted twelve-cell selection to the shared
coding evaluator. It is a synchronous internal API, entered outside an active event
loop, with an explicit transport factory and evidence label. It supplies no default
network transport, approval verifier, retry or launch command. The trusted caller
still owns authenticating actual approval and selecting the reviewed frozen inputs.

Each production-adapter provider pins its first normalized and native request bytes
to the preserved capture. Selected settings, source revision, exact Python entrypoint,
runtime/dependency files, admission bytes, withdrawal and owned listener checks
bracket delegation. Existing native-response guards reject wrong model identity,
missing usage, incomplete native responses and HTTP failures before tools receive
responses. The task guard continues checking fresh source/policy and independent
acceptance around the shared evaluator. Later requests are guarded but are not
claimed to match the scripted reference trajectory.

The fixed schedule retains all twelve task/arm/repeat identities. An exclusive
marker precedes any callback; a durable started state precedes dispatch. Each cell
gets a fresh verified image and the existing owned backend lifecycle. Result rows
are written before provider close and owned cleanup. Only a successful callback,
including private agreeing clean/unforced settlement evidence, changes a started
cell to recorded. Earlier image/session/cleanup evidence hashes are checked before
later dispatch. A known-usage independently rejected artifact can advance; unknown
usage, protocol/source drift, provider/recording/cleanup failure or cancellation
stops the remaining cells. Partial results, consumed markers and failure state stay
retained without reset or resume. A started cell can have a result and does not
therefore count as settled.

The report retains raw results and the full ordinal ledger through the existing
atomic report writer. It adds no aggregation, regrade or model-benefit assessment.
In scripted mode the report is labeled `scripted-real-tools-rehearsal`; that flag
omits live residency observation and does not itself force a supplied transport to
be mocked. A rehearsal caller must supply an internal mock transport explicitly.
In real mode the existing GET-only residency observer records point observations,
not continuous residency or ownership. Setup, image checks, grading and cleanup
remain outside the existing per-task dispatch budget.

Focused tests use mock generation and explicit fake image/backend seams for
orchestration. Native retained proof must separately exercise actual image/backend
ownership with generation blocked from real HTTP before merge. Neither kind of
scripted evidence measures model quality or grants actual inference authority.
The concrete retained freeze, full candidate gates, actual approval and fresh
launch checks remain before any real comparison. These public development tasks
are not held-out evidence; release no-go remains.
