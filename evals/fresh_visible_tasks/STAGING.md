# Fresh capture preservation and exact-path staging

`verify_fresh_capture` checks selected mandatory-mock evidence without a provider,
backend or grading run. It reads the pinned index, private exports and schemas,
fixed twelve-cell order, per-cell receipts and original selected visible tests.
It verifies final reference bytes and bounded final workspace contents, normalized
input identity and production native serialization, scripted result/config/report
correspondence, command environment, response metadata and complete usage totals.
It constructs no inference machinery and does not reobserve historical executable
or dependency paths. Current task/criterion selection still must match its pins.

This is selected-byte/semantic consistency, not authenticated provenance, execution
approval, process isolation or a quality score. Canned accepted references remain
scripted mechanics. An independently selected expected index hash is required;
rehashing unchecked files is not independent evidence selection.

`stage_fresh_capture` first verifies the complete source capture and reserves a new
private archive outside Git, disjoint from the source. It renames the whole consumed
tree into `archive/captured`, preserving selected evidence and unselected caches
without deleting/resetting either. It verifies the moved evidence with its original
absolute workspace roots, then prepares twelve fresh selected arm fixtures at those
same roots. Initial implementations and weak/stronger tests come from the pinned
selection, not from the solved mocked artifacts. All cells must remain unadmitted.

The staged receipt is written last, binding the selection and archive index. Read-only
`verify_staged_fresh` requires that exact receipt, inventory, preserved archive and
fresh cell hashes/modes. Occupied archives, overlap, evidence drift or malformed
selection refuse. Any failure after the move retains the archive and partial fresh
fixtures with no success receipt. There is no automatic rollback, retry or resume.
The rename is not a continuous writer-attribution lease or process-isolation boundary.

The original inputs now refer to the same absolute roots as the new fixtures; this
binds paths for subsequent execution preflight. It does not itself reserve execution
output, attest the runtime/environment, select a backend image, admit the comparison
or construct a real-generation provider. Single-use fixture markers are distinct
from trusted parent execution authority.

Focused real-file tests use an explicitly patched runtime identity for synthetic
capture setup, internal mandatory mocks, the real shared evaluator/tools and external
acceptance. They cover all twelve exact paths, whole-tree byte/mode preservation,
read-only/no-provider verification, historical dependency unavailability, semantic
and native evidence drift even with a reselected outer hash, pre-move refusals,
partial post-move failure and staged receipt/admission/test/inventory drift.
No model-quality or live inference claim follows.
