## Acceptance and mechanism

Count completed-and-independently-accepted /2 per arm; show artifact acceptance,
observed checks, known-budget evidence, unrelated preservation and manual actions
separately. Retain every scheduled row even if blocked, unrun, failed or incomplete.
A partial cohort cannot support an equal-cohort ranking. Visible checks, reference
text resemblance, filename overlap and final-answer prose cannot accept the patch.

Feedback activation requires a real malformed-hash error exposing the treatment
instruction, then a later explicitly supplied current read_file hash and successful
replace_text on the target. Report the intermediate corrected-hash proposal,
validation failures, rereads, budget prevention and whole-file fallback separately.
An immediate valid edit or whole-file success without that feedback is nonactivation,
not proof the diagnostic helped. The provider may still repeat an invalid hash,
escape old_text, run out of time/tokens or produce a wrong patch.

Compare pre-feedback normalized/wire history prefixes and tool choices, not only
first-request hashes. Divergence before changed feedback limits attribution;
identical first inputs do not guarantee identical histories or a causal result.
More accepted completions with activation support only the selected hypothesis;
equal/worse counts or absent activation do not establish a remedy. Temperature-zero
repeats on one public task are not held-out/general/two-model evidence. The basic
accurate diagnostic can remain as usability without a measured quality gain.
