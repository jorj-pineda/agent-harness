# Fresh mandatory-mock owned rehearsal

`rehearse_feedback_execution` creates and consumes its own new rehearsal bundle.
It takes the existing-interpreter preparation inputs, requires synchronous entry,
and first calls the one-shot preparation API. An occupied directory refuses before
admission, so this API cannot consume an existing named candidate bundle. Use a
separate directory for the actual candidate. No installer, resolver, live-mode
switch or caller-supplied transport/provider/approval is exposed.

Preparation makes the selected image and captures/stages eight fresh arm-specific
cells using the existing mandatory mocks. The owned phase then admits only that
new bundle with an explicitly synthetic parent fixture: its ID says
`NOT-actual-approval`, both freeze commit IDs are zero, and its positive fields
exist only to exercise structural admission. This is a deliberate simulation
override, not verification of actual authority, review, CI or merge. The fixture
binds the rehearsal manifest and consumed output; it is not a receipt for a live
candidate or evidence of an authenticated issuer.

Each owned cell uses the shared evaluator, first-input/provider/native guards,
a fresh copied image and the existing independently owned backend lifecycle.
Generation always uses the private HTTPX MockTransport: write the pinned original
reference, run the configured visible check, then finish only after observing its
successful exit. There are three canned responses per owned cell, with simulated
usage of 10 prompt/5 completion tokens per response. The fixed script cannot use
a network delegate, accept a foreign route, continue after close or exceed three
requests. Actual backends are used for metadata/ownership/settlement only; the
user's default 11434 service is never managed.

The returned/written summary binds the selected manifest, preparation receipt,
final report, eight session/cleanup receipts and 72 native evidence files. The
`mock_generation_requests: 24` count covers the **owned execution phase only**;
preparation separately uses 32 mock requests for input capture and its defect/
reference real-tool workflows. Neither count represents model inference or quality.
The owned schedule must finish, every mock must close after exactly three requests,
all eight reference results must complete/accept, and all settlement receipts must
be clean/unforced and agree with their sessions. Native inventories/private modes
are checked before a success summary is written last.

Failures after preparation retain files and attempt withdrawal plus a failure
record. Secondary recording failures are attached to the primary exception. There
is no rollback, retry, resume, cell replacement or inference approval. Evidence
hashes and bounded observations do not provide process isolation, complete import
closure, a future ownership lease or authority to signal historical process groups.
