# Public visible-check comparison proposal

The [closed public pilot](../public_envelope/RESULTS_20261109.md) rejected both
pagination artifacts. The [offline diagnosis](../public_envelope/PAGINATION_DIAGNOSIS_20261110.md)
shows that the bool restriction was supplied, both implementations admit True,
and the visible check omits that restriction. This proposal tests whether making
that existing requirement executable in the visible test helps this model complete
the task within the same limits. It changes no application default.

The [fixed plan](plan.json) is a new public-development comparison, not an
extension/retry of the closed six-cell cohort. **No inference is authorized.**
This PR selects the protocol and semantic treatment only. Exact treatment bytes,
source validation, fresh workspace admission, shared-runtime binding, complete
input capture, mandatory-mock rehearsal, owned execution and a reviewed concrete
freeze/actual approval/fresh launch gates remain before any live request.

## One changed input

Both arms use the original public `paginate_items` request, starting implementation,
independent acceptance and reference. The plan pins the original catalog, source
plan, budget provenance and task tree/request digests. Preserve these inputs;
never edit the original fixture, acceptance, catalog or public-pilot plan.

- **control:** the original visible test unchanged.
- **bool_check:** replace only the fresh workspace's `test_visible.py` with a
  selected file retaining its two original assertions and adding eight cases:
  page versus page_size, True versus False, and empty versus nonempty list.
  Each invalid argument must raise ValueError. Hold the other argument at a valid
  positive integer. The implementation stays byte-for-byte identical initially.

Both arms expose the same tools, request and configured check filename/argv. The
model may read the visible test before editing; this intervention includes that
availability as well as executed check feedback. It is **not** a feedback-only
causal isolation. Test source and check output add context/time inside the existing
budgets, without compensating allowances. The new file must be selected and
validated before capture; semantic prose alone is not an executable precondition.

The added cases derive only from the explicit public requirement. Do not copy
private held-out tests or expose independent acceptance to the agent. Ordinary
visible tests remain editable; weakening them never changes external acceptance.

## Fixed cells and limits

Use only local gemma4:12b and Ollama 0.33.2 with the digest in the plan,
direct/whole_file_check, temperature zero, thinking off, context 16384 and
keep-alive 300. Select the same independently owned backend lifecycle for both
arms, with a fresh image/workspace per cell; never manage the user's 11434 service.

Four independent paired repeats have fixed arm order:

| Repeat | First cell | Second cell |
|---|---|---|
| 1 | control | bool_check |
| 2 | bool_check | control |
| 3 | control | bool_check |
| 4 | bool_check | control |

This balances order; it does not remove all environment or cache effects. No
warmups, resubmissions, replacement cells, manual rescue, arm reordering or extra
attempts. Do not use old artifacts as starting workspaces. Repeats are planned
observations, not retries. All eight cells use harness mode; control is the old
visible check, not the evaluator's minimal-prompt baseline mode.

Per cell retain 150 dispatch seconds, 32K total/4096 output tokens, 12 tools,
six iterations, request output cap 2048/minimum 256, two touched files and
`python -m pytest -q test_visible.py`. Complete Settings must bind every remaining
field before execution. Aggregate reservations are 1200 dispatch seconds, 256K
total tokens, 32,768 output tokens, 96 tools and 48 iterations. Setup, image
verification, grading, review and cleanup are outside dispatch. These sums are
neither expected costs nor hard end-to-end deadlines; budgets cannot transfer.

Artifact rejection or iteration exhaustion may advance after the result is
preserved and settlement is clean. Unknown submission/usage, provider/transport/
HTTP failure, input/runtime/model/environment/criterion drift, failed preservation
or failed/forced cleanup stops the cohort; preserve failed/stopped/unrun cells.
No downloads, installs, hosted/paid calls, model switch or user-service changes.

## Evidence and decision rule

Record complete settings, environment, runtime/dependency/binary/image selection,
exact named workspace inputs, normalized/native first requests, native responses,
tool traces, diffs, visible check results, completion/verification states, usage,
scoped timing and owned settlement. Record results before cleanup and advance only
after settlement. Regrade preserved final artifacts on copies with unchanged
independent acceptance; archive both initial and final visible tests to expose
test weakening. Hashes describe bounded observations, not authentication/isolation.

Primary outcomes are accepted and completed-and-accepted counts per arm, with all
four paired outcomes shown. Report visible pass/failure separately, interventions,
regressions, tool misuse, token/time use and unknown totals. Do not infer task
success from file overlap, final prose, a visible pass or a finished ledger.

Only describe the candidate as a promising **public-task follow-up** if it produces
more completed-and-accepted artifacts than control without introducing new
independent-acceptance regressions or manual rescue. Ties, stopped cohorts and
unknown results establish no benefit. Report all cells regardless of outcome;
no post-hoc task selection, threshold changes or promotion to defaults.

Four repeats of one known task with one model are development evidence with
limited variation. Even a favorable difference does not establish a general or
held-out improvement, a reliable feature envelope, or closure of G2–G5. Preserve
the original 4/6 public and 2/10 project results, 8/10 target and release no-go.

## Implementation sequence for this comparison

1. Protocol and fixed semantic schedule (this proposal).
2. Exact treatment bytes, bounded original-source/treatment validation and refusal
   regressions; prove old defective artifacts fail while the reference passes.
3. Fresh arm-specific workspace preparation/admission and shared evaluator binding,
   retaining original grading and refusing source drift.
4. Mandatory-mock rehearsal and normalized/native first-input capture for both arms.

Those four slices prepare the experiment. A separate reviewed retained preparation,
concrete execution freeze, actual approval and fresh launch gates are still needed
before live inference. A scripted successful correction proves mechanics only.
