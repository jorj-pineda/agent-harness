## Operator boundary

The copied recipe must be started with the selected existing interpreter, the
retained runtime on PYTHONPATH, and its working directory set to that runtime.
`check_candidate` checks that exact source location/revision, external interpreter,
manifest, full current preflight, selected passing gate and free owned port.
Check-only constructs no approval, provider or admission and grants no lease.

Mode selection is mandatory and mutually exclusive: `--check-only` or `--execute`.
Execute additionally requires the actual parent-selected receipt path/hash and
exact reviewed/merged freeze commits. It checks a two-parent merge whose second
parent is the reviewed head, runtime ancestry, and the specification from that
exact reviewed Git object. Recipe/gate/manifest/runtime and both evidence-index
byte hashes must match. Local Git and hashes cannot authenticate the issuer,
review, CI, user authority or the source of those command arguments.

The actual authorized parent must independently verify those facts and retained
artifacts before issuing a receipt or supplying execution arguments. Synthetic
rehearsal/probe receipts are not actual authority. This PR issues none and does not
execute the candidate. Admission precedes construction of a zero-retry transport
with environment proxies disabled. Shared runtime/input/usage/ownership guards,
native evidence and fresh per-cell images/backends remain enforced.

Unknown submission/usage, HTTP/transport/runtime/model/input/environment/criterion
or preservation drift and failed/forced cleanup stop later dispatch. Preserve
partial results and unrun slots; do not reset or retry. Rejection or iteration
exhaustion may advance only after known usage, result preservation and clean
settlement. A visible pass or ledger completion is not independent acceptance.
