## Remaining gates and operator limits

The actual parent must independently verify the exact proposal head, complete source
and retained evidence, applicable local gates, both CI checks and the two-parent
merge, then decide whether user authority and every prerequisite permit issuing an
actual receipt for the exact candidate hash/runtime. The recipe loads the freeze
spec from the exact reviewed Git object, checks recipe/G0/manifest/runtime bindings,
second-parent identity and runtime ancestry. Local Git and affirmative JSON cannot
authenticate the receipt issuer, review results, CI or source of the command arguments.

The recipe requires explicit mutually exclusive `--check-only` or `--execute`.
Check-only creates no approval/provider/admission. Execute requires all actual
parent-selected receipt/hash and reviewed/merged commit arguments. It admits before
creating its zero-retry, environment-proxy-disabled transport. Before any delegation,
fresh selected-artifact, source/withdrawal, Settings/input and owned-resource checks
must pass; every cell uses a fresh image and owned 11447 lifecycle. The user's 11434
service is never managed, unloaded, reconfigured or stopped.

Artifact rejection or iteration exhaustion may advance only after its result is
recorded with known usage and clean settlement. Unknown submission/usage, received
HTTP refusal, transport/runtime/model/environment/criterion/preservation drift or
failed/forced cleanup stops; later cells remain unrun. No resubmission or reset.
Preserve results before cleanup and inspect/regrade final artifacts on copies using
the unchanged original acceptance criteria. A visible check is not acceptance.

Selected dependency files and distribution versions do not establish complete import
or shared-library closure. Metadata is not authenticated model identity. Observations
are bounded and non-atomic, not isolation, a current resource lease or continuous
residency/cache reuse. Historical settled groups are not authority to signal a new
group. Six cells on three public tasks and one model do not close repeated held-out,
two-model or real-project release gates. The existing release no-go stays in force.
