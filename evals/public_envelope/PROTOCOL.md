# Public development task-envelope pilot

The closed whole-file fixed-check attempt edited code, passed its visible check
and returned an answer, but independent acceptance rejected a missed formatting
requirement. Further interface tuning is not yet justified by that outcome.
This pilot measures a broader task envelope using existing independent criteria.
It is one recorded policy, not a baseline comparison or a causal experiment.

The fixed six cells use the first public-development editing task in each
category, in catalog order: divide_zero (bugfix), paginate_items (feature), and
extract_label_normalizer (refactor), then the same order for repeat 2. Selection
is fixed before generation, not conditioned on model successes. Requests,
fixtures, acceptance and references are unchanged; file bytes and modes are pinned. The task
catalog and original budget-plan bytes are pinned too. Hashes describe bounded,
non-atomic file observations; they do not provide isolation or approval authority.

Use only the previously selected local gemma4:12b digest and Ollama 0.33.2,
direct/whole_file_check, temperature zero, thinking off, context 16384 and
keep-alive 300. Each cell retains the original limits: 150 dispatch seconds,
32K total/4096 output tokens, 12 tools, six iterations, request cap 2048/minimum
256, two touched files and the configured `python -m pytest -q test_visible.py`
check. No budget transfer, extra attempt, warmup, control, substitution or manual
patch repair. Six cells reserve at most 900 dispatch seconds, 192K total tokens,
24,576 output tokens, 72 tools and 36 iterations. Setup, grading and preservation
remain outside dispatch; those sums are not hard end-to-end limits or predictions.

The plan validator checks the exact reviewed plan bytes, original budget shape,
current catalog and all three selected trees per task, and the exact six-cell
order. It does not create a provider, workspace, service, output or parent receipt.
It grants no inference authority. The old held-out executor and its ordinal-2
freeze recipes are not an execution path for these public tasks.

Before any generation, separately implement and rehearse shared-runtime execution
and evaluation-owned workspace preservation; pin named first inputs, Settings,
environment, runtime/dependencies/executables/image and original criteria. Require
fresh separate rehearsal/candidate bundles, mandatory-mock contract evidence,
refusal and owned-settlement checks, concrete exact-head freeze review, applicable
local gates, both CI checks, merge, actual parent receipt and fresh launch gates.
No downloads/installs, Docker, hosted/paid calls or management of the user's
Ollama service on 11434. Manage only independently owned 11447 resources after
ownership checks. No premium model becomes a product dependency.

Artifact rejection or iteration exhaustion alone may advance to the next planned
cell after recording and clean settlement. Unknown submission or usage, transport,
HTTP, runtime, model/environment/criterion/preservation drift, or failed/forced
settlement stops the cohort. Keep failed, rejected, cancelled and unrun rows;
never retry or replace a cell. Repeats are independent planned attempts, not rescues.

Report accepted and completed-and-accepted counts separately by task/category,
completion and visible-check states, actual changes, refusals, usage and scoped
timings. Regrade final artifacts with unchanged authoritative criteria on copies.
A passing visible check does not establish independent acceptance. Six cells on
three public tasks and one model do not satisfy repeated held-out/two-model or
real-project release criteria. Do not infer a policy gain, general capability,
default adoption, continuous residency, cache reuse or release readiness.
